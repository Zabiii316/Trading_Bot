# Phase 5 — Order-Flow Feature Engine

## Purpose

Phase 5 turns replayed or live trade/book events into deterministic microstructure features for the liquidity-sweep signal stack. It is intentionally incremental: the hot path keeps only a rolling trade window, CVD, and the previous/current top-depth book views.

## Inputs

- `RawTradeEvent`
- `RawAggTradeEvent`
- `OrderBookSnapshotEvent`
- `DepthUpdateEvent`
- `ReconstructedBookEvent` / `BookView` generated by the local order-book service

## Output

- `OrderFlowFeatureEvent`

## Features

### Delta

```text
Delta = aggressive_buy_volume - aggressive_sell_volume
```

### Normalized delta

```text
NormalizedDelta = Delta / (aggressive_buy_volume + aggressive_sell_volume)
```

The engine infers aggressive side from Binance maker flags already normalized by Phase 2.

### Cumulative volume delta

```text
CVD_t = CVD_{t-1} + signed_trade_quantity_t
```

CVD is cumulative from engine start or replay start. Production deployments should reset it at explicit session boundaries if desired.

### Queue imbalance

```text
QI_N = (sum_bid_depth_N - sum_ask_depth_N) / (sum_bid_depth_N + sum_ask_depth_N)
```

L1, L5 and L10 are emitted by default.

### Best-level OFI

Best-level OFI follows the standard event-based interpretation:

- bid price increases: positive current bid size
- bid price decreases: negative previous bid size
- same bid price: current bid size minus previous bid size
- ask price decreases: negative current ask size
- ask price increases: positive previous ask size
- same ask price: previous ask size minus current ask size

### Multi-level OFI

L5 OFI compares the union of previous/current top-N prices:

```text
OFI_N = sum(current_bid_qty - previous_bid_qty) - sum(current_ask_qty - previous_ask_qty)
```

This captures depth additions/removals beyond the best level.

### Absorption ratio

```text
AbsorptionRatio = rolling_aggressive_volume / max(abs(current_mid - previous_mid), epsilon)
```

High values indicate that aggressive volume produced limited price movement. Downstream scoring must normalize this by symbol/regime distribution.

### Depletion and replenishment

```text
DepletionSide = max(0, previous_depth - current_depth) / previous_depth
ReplenishmentSide = max(0, current_depth - previous_depth) / previous_depth
```

These are calculated for bid and ask sides using the configured top depth.

## Performance design

- Rolling trade window uses `deque` with maintained counters.
- CVD is updated per trade without scanning history.
- Queue imbalance scans only top-N levels.
- OFI compares only previous/current top-N snapshots.
- Contract serialization is isolated at the event boundary.
- Raw precision remains in storage; floats are used internally for hot-path calculations.

## Failure mode

If a book event is sequence-unhealthy, the engine clears book context and refuses to calculate features until a new healthy book view arrives. This prevents signal generation from corrupted depth state.
